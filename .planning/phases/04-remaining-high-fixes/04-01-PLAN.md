<action>
In `src/sva2rtl/ast_importer.py`, in the `_build_seq_repetition()` function, after parsing `rep_min` and `rep_max`, add two validations:

1. **Check `rep_min > rep_max`**: If the minimum count exceeds the maximum, raise `SvaCompileError` with message `"Invalid repetition range: [*{rep_min}:{rep_max}] — min must be <= max"` and include `source_loc`. This mirrors the existing delay range validation in `_build_seq_concat()`.

2. **Reject `[*0]` (both min and max are 0)**: If `rep_min == 0 and rep_max == 0`, raise `SvaCompileError` with message `"[*0] repetition (zero-length match) is not supported. Use ... to ..."`. Zero-match repetition has no practical hardware implementation and would produce ambiguous RTL. Include source location in the error.

Validation order: check `rep_min > rep_max` first, then check `rep_min == 0 and rep_max == 0`.
</action>

<action>
In `src/sva2rtl/composer.py`, rewrite `_collect_signals()` (lines 742-751) to preserve the first observed `(port_name, sig_name)` pair for each unique port name, instead of reconstructing as `(name, name)`.

**Before (buggy)**:
```python
def _collect_signals(children: list[CheckerNode]) -> tuple[tuple[str, str], ...]:
    seen: dict[str, None] = {}
    for child in children:
        for port_name, sig_name in child.observed_signals:
            if port_name not in seen:
                seen[port_name] = None
    return tuple((name, name) for name in seen)
```

**After (fixed)**:
```python
def _collect_signals(children: list[CheckerNode]) -> tuple[tuple[str, str], ...]:
    result: dict[str, str] = {}
    for child in children:
        for port_name, sig_name in child.observed_signals:
            if port_name not in result:
                result[port_name] = sig_name
    return tuple((p, s) for p, s in result.items())
```

**Do NOT modify `extract_signals()`**: It extracts signal names from expression text, where `port_name` and `sig_name` are inherently identical. Its `(name, name)` behavior is correct.
</action>
