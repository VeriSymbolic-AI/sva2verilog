<task type="auto">
  <name>Task 3: Create Verilator C++ wrapper Jinja2 template</name>
  <files>tests/simulation/wrapper.cpp.j2</files>
  <action>
    Per D-03 and RESEARCH.md Pattern 1: create `tests/simulation/wrapper.cpp.j2` — a Jinja2 template that generates a minimal C++ testbench for Verilator.

    The template receives these Jinja2 variables at render time:
    - `module_name`: str — DUT module name
    - `clock_signal`: str — clock port name (typically "clk")
    - `extra_inputs`: list[str] — all non-clock, non-rst_n, non-disable_i input port names (e.g. ["start", "sig1", "sig2"])
    - `stimulus`: list[dict] — per-cycle stimulus dicts with keys from extra_inputs + optional "disable_i"
    - `has_overflow_flag`: bool — whether to print a 4th column for overflow_flag

    The generated C++ must:
    1. `#include "V{{ module_name }}.h"`, `#include "verilated.h"`, `#include <cstdio>`
    2. Instantiate `VerilatedContext` and `V{{ module_name }}` model
    3. Initialize all inputs to 0 (clk, rst_n, start, disable_i, extra_inputs)
    4. Run 2 full clock cycles with rst_n=0 (reset sequence: for each of 2 cycles: timeInc+clk=1+eval, timeInc+clk=0+eval)
    5. Release rst_n=1 (set before next posedge)
    6. For each stimulus cycle: drive inputs while clk=0 → eval() → timeInc+clk=1 → eval() → printf outputs → timeInc+clk=0 → eval()
    7. Use `printf("%c %c %c\n", top->active?'1':'0', top->pass?'1':'0', top->fail?'1':'0')` (3-column) or with overflow_flag as 4th column
    8. Call `top->final()`, delete top, delete contextp, return 0

    Per RESEARCH.md Pitfall 1: Use `--exe --build --timing` in the compilation command (NOT `--binary`). This template is for the wrapper only — the compilation command lives in tb_generator.py.

    Per RESEARCH.md Pitfall 3 (clock edge semantics): Drive inputs while clk=0, eval, then toggle to clk=1, eval, capture outputs, then toggle back to clk=0, eval.

    Per RESEARCH.md code examples: use `top->{{ sig }} = {{ 1 if stim.get(sig, False) else 0 }};` for stimulus signal driving. Use `top->disable_i = {{ 1 if stim.get('disable_i', False) else 0 }};` for disable.

    Do NOT hardcode module_name — use Jinja2 `{{ module_name }}` throughout.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI/env → pytest | `--simulator` value and `SVA2RTL_SIMULATOR` cross from user/CI environment into test framework |
| Jinja2 template → C++ compiler | Stimulus data embedded in generated C++ crosses from Python test data into compiled native code |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | pytest_addoption --simulator | mitigate | `choices=("iverilog", "verilator")` restricts values; invalid input rejected by argparse before any code runs |
| T-02-02 | Information Disclosure | SVA2RTL_SIMULATOR env var | accept | Env var contains only simulator name; no secrets or PII |
| T-02-03 | Elevation of Privilege | wrapper.cpp.j2 stimulus embedding | accept | Stimulus data originates from Python test code (trusted); C++ wrapper runs in subprocess with same privilege as test process |
| T-02-04 | Denial of Service | shutil.which() PATH check | accept | Missing simulator → pytest.skip(), not crash; no resource exhaustion vector |
| T-02-SC | Tampering | pip/cargo installs | accept | No new pip/npm packages added in this plan; Verilator installed via system package manager |
</threat_model>
