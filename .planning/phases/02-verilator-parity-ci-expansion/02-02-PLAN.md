  <files>tests/simulation/tb_generator.py</files>
  <action>
    Per D-03 and RESEARCH.md Pattern 1 &amp; Code Examples: implement the Verilator simulation backend.

    **Part A — `_generate_verilator_wrapper()`:**

    Create a private function that loads `wrapper.cpp.j2` via Jinja2 and renders it:

    ```python
    def _generate_verilator_wrapper(
        module_name: str,
        clock_signal: str,
        extra_inputs: list[str],
        stimulus: list[dict[str, Any]],
        has_overflow_flag: bool,
    ) -> str:
    ```

    Implementation:
    - Use `jinja2.Environment(loader=jinja2.FileSystemLoader(...))` with the loader pointing to the directory containing `wrapper.cpp.j2`. Compute the template directory relative to `__file__`: `Path(__file__).parent`.
    - `env.get_template("wrapper.cpp.j2")` → `template.render(module_name=..., clock_signal=..., extra_inputs=..., stimulus=..., has_overflow_flag=...)`
    - Return the rendered string.

    **Part B — `_run_simulation_verilator()`:**

    Create a private function:

    ```python
    def _run_simulation_verilator(
        module_name: str,
        sv_sources: list[str],
        tb_code: str,  # ignored — Verilator uses C++ wrapper, not SV testbench
        *,
        work_dir: Path,
        has_overflow_flag: bool,
    ) -> list[dict[str, bool]]:
    ```

    This function needs the `stimulus` and `extra_inputs` data, but they're not in the current `run_simulation()` signature. To bridge this gap, `_run_simulation_verilator()` must extract stimulus from `tb_code` (the generated SV testbench string). Parse the stimulus from the SV testbench by extracting the initial block stimulus assignments.

    Alternative (cleaner): Instead of parsing tb_code, add `stimulus` and `extra_inputs` as optional keyword-only parameters to `run_simulation()` and pass them through to the verilator backend:

    ```python
    def run_simulation(
        ...,
        simulator: str = "iverilog",
        stimulus: list[dict[str, Any]] | None = None,
        extra_inputs: list[str] | None = None,
        clock_signal: str = "clk",
    ) -> list[dict[str, bool]]:
    ```

    When `simulator == "verilator"`, `stimulus` and `extra_inputs` are REQUIRED — raise `ValueError` if missing.

    Implementation of `_run_simulation_verilator()`:
    1. `shutil.which("verilator")` — raise RuntimeError if not found
    2. Write DUT source: `(work_dir / "dut.sv").write_text("\n\n".join(sv_sources))`
    3. Generate wrapper: `wrapper_code = _generate_verilator_wrapper(module_name, clock_signal, extra_inputs, stimulus, has_overflow_flag)`
    4. Write wrapper: `(work_dir / "wrapper.cpp").write_text(wrapper_code)`
    5. Compile with Verilator: `subprocess.run([verilator, "--exe", "--build", "--timing", "-Wall", "--top-module", module_name, "-o", str(work_dir / "Vdut"), str(work_dir / "dut.sv"), str(work_dir / "wrapper.cpp")], cwd=str(work_dir), capture_output=True, text=True)`
       - Per RESEARCH.md: use `--exe --build --timing`, NOT `--binary`. `--binary` includes `--main` which conflicts with our wrapper's `main()`.
    6. If compile fails → raise RuntimeError with stdout/stderr
    7. Run simulation: `subprocess.run([str(work_dir / "Vdut")], capture_output=True, text=True)`
    8. If simulation fails → raise RuntimeError with stdout/stderr
    9. Return `_parse_output(sim_result.stdout, has_overflow_flag=has_overflow_flag)`

    IMPORTANT: Verilator compilation produces artifacts in `work_dir/obj_dir/`. The `-o` flag places the binary. The exact binary path depends on Verilator version — check if it's `work_dir/Vdut` or `work_dir/obj_dir/Vdut`. Use `-o` with the absolute path `str(work_dir / "Vdut")` and verify the binary exists there after compilation.

    IMPORTANT: The `--timing` flag is included per D-03 locked decision. Per RESEARCH.md Pitfall 2, our DUT has no timing constructs but overhead is negligible.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Python → Verilator subprocess | DUT SV source and wrapper C++ cross from Python into Verilator compiler |
| Verilator → g++ | Verilator-generated C++ crosses into system compiler |
| Native binary → stdout | Simulation output crosses from native process back to Python via pipe |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Tampering | subprocess.run verilator args | mitigate | Module name from CheckerNode (internal, not user-controlled); file paths use pathlib; shell=False by default in subprocess.run |
| T-02-06 | Elevation of Privilege | Native binary execution | accept | Binary compiled from trusted SV + template-generated C++; runs with same user privilege as test process; no setuid |
| T-02-07 | Denial of Service | Verilator compilation | accept | Compilation time bounded by pytest-timeout (120s per test); individual test timeout catches hangs |
| T-02-08 | Information Disclosure | Simulation stdout | accept | stdout contains only simulation results (0/1 characters); no secrets or PII |
| T-02-SC | Tampering | pip/cargo installs | accept | No new pip packages; jinja2 already in project dependencies |
</threat_model>
