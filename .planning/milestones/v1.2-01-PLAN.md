## Plan Decomposition

### Plan 1-1: yosys/sby CLI Integration (`sva2rtl --verify`)

**Objective:** Add `--verify` flag that generates both unoptimized and optimized RTL, then runs yosys equivalence checking.

**Technical Design:**

Pipeline flow:
```
SVA source → slang parse → IR → normalize → compose → 
  ├─ Emit unoptimized RTL (skip optimizer) → unoptimized.sv
  └─ Emit optimized RTL (full pipeline)     → optimized.sv
→ yosys equiv_make unoptimized.sv optimized.sv
→ yosys equiv_induct
→ Parse output → PASS/FAIL/INCONCLUSIVE
```

yosys script:
```tcl
read_verilog -sv unoptimized.sv
read_verilog -sv optimized.sv
proc;;
equiv_make gold gate equiv
equiv_induct
equiv_status
```

**Files to create/modify:**
- `src/sva2rtl/formal.py` — New module: yosys integration
- `src/sva2rtl/cli.py` — Add `--verify` flag
- `tests/test_formal.py` — Formal verification test fixtures

**Key design decisions:**
1. yosys invoked as subprocess (same pattern as slang CLI) — no in-process binding
2. Unoptimized version generated by temporarily disabling optimizer passes
3. Formal proof attempts equiv_induct first; falls back to bounded check with BMC

### Plan 1-2: Per-pass Formal Equivalence Tests

**Objective:** For each of the 5 optimizer passes, create a dedicated formal test proving input→output equivalence.

**Strategy:** For each pass, take a minimal SVA property that exercises the pass's transform:
- `constant_fold`: Property with constant expressions → verify folded vs unfolded equivalent
- `concat_merge`: Property with mergeable concat operations
- `cse`: Property with common sub-expressions → verify deduplication is equivalence-preserving
- `counter_merge`: Property with mergeable counters → verify merged counters equivalent
- `dead_node`: Property with dead branches → verify removal preserves behavior

**Implementation approach:**
1. Create minimal SVA inputs that trigger each pass
2. Compile: once with all passes, once with the target pass disabled
3. Run yosys equiv_induct on the pair
4. Assert PASS

**Test file:** `tests/test_formal_passes.py`

### Plan 1-3: Template-level Formal Verification

**Objective:** Verify that all 11 templates + 2 macros produce equivalent RTL with and without optimization.

**Template coverage:**
- `seq_concat_top` — sequence concatenation
- `disable_iff_top` — disable iff wrapper
- `overlap_bitvec` / `nonoverlap` — implication
- `rep_consecutive` — consecutive repetition
- `delay_fixed` / `delay_range` — delays
- `rose` / `fell` / `stable` — signal functions
- `past` — past value
- Plus 2 Jinja2 macros

**Implementation:** Generate test SVA for each template, run formal equivalence.

### Plan 1-4: CI Integration

**Objective:** Add conditional formal verification job to CI matrix.

**Constraints:**
- yosys available on Linux CI runners; NOT available on macOS CI runners
- Formal verification adds ~30-60 seconds per test
- Should not block non-formal jobs
- Should be a GitHub Actions job with `if: runner.os == 'Linux'`
