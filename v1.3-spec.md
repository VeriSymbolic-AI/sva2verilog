# sva2rtl v1.3 Tier 2 Operators — Specification

## Goal

Extend sva2rtl to support Tier 2 SVA operators (sequence operators, property-level operators, and repetition variants) currently deferred from v1.2. Establish an NFA-based composition architecture as the foundation for multi-path sequence operators, and implement cross-property CSE optimization.

## Why v1.3 Is Architecture-First

The current token-passing composition model is single-path: tokens flow linearly through sequence elements, with delay counters gating progress. This cannot express multi-path sequence operators:

- `intersect` — two sequences must complete simultaneously (AND of two token paths)
- `within` — one sequence must complete contained within another's evaluation window
- `throughout` — a condition must hold continuously throughout another sequence
- `first_match` — only the earliest completion counts (multiple paths, earliest wins)
- `[->N]` (goto) — N occurrences, not necessarily consecutive (liveness tracking)
- `[=N]` (non-consecutive) — N occurrences, with no constraint after the last

These require either NFA-style automata composition (each operator is an automaton, composed via product/synchronization) or significant token-passing extensions (fork/join, multi-token arbitration). A research spike at Phase 1 will determine the architecture before implementation begins.

## Phase Plan (4 phases)

### Phase 1: Architecture Research Spike (1 plan)

**Goal:** Determine whether NFA composition or token-passing extensions are the right foundation for Tier 2 operators.

**Requirements:**
- ARCH-01: Evaluate NFA automata composition for multi-path operators (intersect, within, throughout, first_match)
- ARCH-02: Evaluate token-passing fork/join extensions for the same operators
- ARCH-03: Compare against industry approaches (Cadence JasperGold, Synopsys VC Formal, sv2v/Yosys formal assertions)
- ARCH-04: Produce a decision document with rationale, prototype sketches, and expected complexity estimates

**Success criteria:**
1. Architecture decision documented with clear rationale
2. Complexity estimates for each Tier 2 operator under both architectures
3. Prototype sketches for the 2 hardest operators (intersect, throughout) under the chosen architecture

### Phase 2: IR Expansion + Simple Operators (3 plans)

**Goal:** Expand IR node types for new operators; implement the simplest Tier 2 operators first to validate the architecture.

**Requirements:**
- IR-01: New IR node types: `SeqIntersect`, `SeqWithin`, `SeqThroughout`, `SeqFirstMatch`, `SeqGotoRep`, `SeqNonconsecRep`, `PropAnd`, `PropOr`, `PropNot`, `SignalChanged`
- OPS-01: `$changed` — signal changed since previous cycle (trivial: `sig != sig_prev`)
- OPS-02: `first_match` — earliest completion wins (subsumption of later matches)
- OPS-03: `[->N]` (goto repetition) — N non-consecutive occurrences, liveness tracking
- OPS-04: `[=N]` (non-consecutive repetition) — N occurrences, relaxed tail

**Success criteria:**
1. All 4 new operators pass dual-oracle simulation
2. AST importer recognizes new operator kinds with clear errors for unsupported configs
3. 20+ dedicated per-operator test cases

### Phase 3: Complex Sequence Operators (2 plans)

**Goal:** Implement the multi-path sequence operators that required the architecture decision.

**Requirements:**
- OPS-05: `intersect` — two sequences complete simultaneously
- OPS-06: `within` — one sequence completes contained within another
- OPS-07: `throughout` — condition holds continuously through a sequence
- OPS-08: `and` (sequence) — both sequences match, same start
- OPS-09: `or` (sequence) — either sequence matches

**Success criteria:**
1. All 5 complex operators pass dual-oracle simulation
2. Behavioral oracle extended to model intersect/within/throughout
3. Formal equivalence tests for the composed checker trees

### Phase 4: Property Operators + CSE + Release (2 plans)

**Goal:** Add property-level operators, implement cross-property CSE, and release.

**Requirements:**
- OPS-10: `not` (property) — invert pass/fail
- OPS-11: `if...else` (property) — conditional property selection
- CSE-01: Cross-property CSE optimization (share identical sub-checkers across root nodes)
- RELEASE: Tag v1.3.0, release notes, CI green

**Success criteria:**
1. All Tier 2 operators pass dual-oracle + formal
2. Cross-property CSE reduces module count by ≥30% on multi-property benchmarks
3. CI green on full matrix

## Explicitly NOT in v1.3

- Temporal operators (`nexttime`, `always`, `eventually`, `until`) — defer to v1.4
- Sequence `intersect`/`within` with local variables — defer to v1.4
- NFA composition for nested multi-path — defer to v1.4 (v1.3 does single-level)
- Unbounded repetition (`[*]`, `[+]`) — inherently not synthesizable
- Multi-clock properties — defer to v2
- C++ rewrite — defer to v2

## Operator Complexity Ranking

| Operator | Complexity | Reason |
|----------|-----------|--------|
| `$changed` | Low | Trivial: `sig != sig_prev`, no new composition needed |
| `first_match` | Medium | Earliest-wins subsumption; needs new template, existing composition |
| `not` | Low | Invert pass/fail output |
| `if...else` | Low | Multiplex between two properties |
| `[->N]` | Medium-High | Liveness counter with non-consecutive matching |
| `[=N]` | Medium-High | Like goto but with relaxed tail |
| `and` (seq) | High | Two-path synchronization; needs arch decision |
| `or` (seq) | High | Two-path choice; needs arch decision |
| `intersect` | High | Two-path simultaneous completion; needs arch decision |
| `within` | High | Containment check; needs arch decision |
| `throughout` | High | Continuous condition spanning sub-sequence; needs arch decision |

## Validation Strategy

- **Architecture**: Research spike with prototype sketches before implementation
- **Simulation**: Dual-oracle (iverilog + Verilator) for all new operators
- **Behavioral oracle**: Extend SVABehavioralSim for new operator semantics
- **Formal**: yosys equiv_induct per-operator and template-level
- **Nyquist**: Dedicated coverage tests per new operator
