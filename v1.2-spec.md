# sva2rtl v1.2 Quality-First Hardening — Specification

## Goal

Establish formal verification infrastructure for the sva2rtl optimizer pipeline, close all remaining Nyquist coverage gaps, harden input handling, complete the behavioral oracle, and clean up deferred MEDIUM/LOW debt. No new SVA operators — pure quality assurance milestone.

## Why v1.2 Is Quality-First

A deep diagnostic review (2026-06-12) of the v1.1 codebase identified the following critical gaps:

1. **Zero formal verification**: All 736 tests are simulation-based. The 5-pass optimizer (constant_fold, concat_merge, cse, counter_merge, dead_node) transforms the generated RTL but these transforms have never been formally proven to preserve semantic equivalence. With yosys/sby, we can prove equivalence for all possible inputs, not just the finite traces covered by simulation.

2. **6 remaining Nyquist BLOCKING gaps**: NYQ-01 (vacuous satisfaction), NYQ-02 (strong()), NYQ-10 (M>N range delay), NYQ-11 (concurrent attempt stress), NYQ-22 (deep $past), NYQ-30 (token duplication invariant) — all identified but never addressed with dedicated tests.

3. **Input handling fragility**: `_extract_clock` has a silent posedge default, `_build_seq_repetition` can emit `<expr>` placeholder into generated RTL, `_compose_repetition` silently degrades on non-BoolExpr sub-expressions.

4. **Behavioral oracle incomplete**: Oracle models per-operator disable behavior but cannot model composed checker hierarchy; missing oracle integration for disable_iff_top and seq_concat_top test suites.

5. **8 deferred MEDIUM/LOW items** from v1.1 Phase 6 triage.

## Phase Plan (6 phases)

### Phase 1: Formal Equivalence Verification Infrastructure (4 plans)

**Requirements:**
- FORMAL-01: yosys and sby are installed and integrated via `sva2rtl --verify` CLI flag. Pipeline: compile → compose → generate unoptimized.sv and optimized.sv → yosys equiv_induct proof.
- FORMAL-02: Each of the 5 optimizer passes has a dedicated formal equivalence test proving input→output semantic equivalence under all inputs.
- FORMAL-03: All 11 templates + 2 macros are verified: compose() output is formally equivalent to optimizer output for every template path.
- FORMAL-04: Formal verification is added to CI matrix as conditional job (Linux-only; macOS CI skips formal due to yosys availability).

**Success criteria:**
1. Running `sva2rtl --verify foo.sv` produces a PASS/FAIL verdict from yosys equiv_induct.
2. 5 dedicated formal tests (one per optimizer pass) pass under sby.
3. All 11 templates pass formal equivalence between unoptimized and optimized RTL.
4. CI shows green on the formal verification job for every commit.

### Phase 2: Nyquist Gap Remediation (3 plans)

**Requirements:**
- NYQ-01: Dedicated test verifying that a Boolean property whose precondition never fires reports attempt_fired=0 (not stuck in unknown state).
- NYQ-02: `strong()` produces a clear compile error with source location (currently zero handling in codebase).
- NYQ-10: `##[M:N]` with M>N produces a clear compile error with source location; dedicated negative tests exist.
- NYQ-11: Concurrent attempt stress test for `##N` fixed delay — precondition fires every cycle for 2×N cycles; verify correct token management.
- NYQ-22: `$past(sig, n)` with n > 100 emits a warning; n exceeding practical hardware depth is flagged.
- NYQ-30: Programmatic token-count invariant check verifies token-passing composition engine correctly duplicates tokens at sequence branches.

**Success criteria:**
1. 6 dedicated test files exist, one per NYQ gap.
2. All existing 736 tests + new Nyquist tests pass under dual-oracle (iverilog + Verilator).
3. No Nyquist BLOCKING gaps remain open.

### Phase 3: Composer & Importer Input Hardening (2 plans)

**Requirements:**
- HARDEN-09: `_extract_clock` raises error when edge field is missing (no silent posedge default).
- HARDEN-10: `_build_seq_repetition` raises error on empty expr field (no `<expr>` placeholder in generated RTL).
- HARDEN-11: `_compose_repetition` handles non-BoolExpr sub-expressions gracefully; signal extraction uses a safe fallback that does not produce `<expr>` in output.

**Success criteria:**
1. Malformed AST inputs produce clear, early error messages — never silent fallbacks.
2. No `<expr>` placeholder can appear in generated RTL under any input.
3. All existing 736 tests + new negative tests pass.

### Phase 4: Behavioral Oracle Completion (2 plans)

**Requirements:**
- ORACLE-01: Extend SVABehavioralSim to model composed checker hierarchy (disable_iff_top wrapping, seq_concat_top wrapping) so that simulation tests can use the oracle as a per-cycle reference for composite assertions.
- ORACLE-02: Wire oracle comparison into all existing sim test suites (disable_iff, named_seq) where oracle was previously unused.

**Success criteria:**
1. All 65 simulation oracle tests now compare against SVABehavioralSim per-cycle output, not just hardcoded expected patterns.
2. Oracle correctly models disable_iff + implication nested composition.
3. Oracle correctly models seq_concat with embedded delay operations.

**Success criteria:**
1. All 8 deferred MEDIUM/LOW items are closed (with commit SHA) or formally deferred with rationale.
2. Normalizer dead code is removed.
3. All 736 regression tests + 65 simulation oracle tests pass.

### Phase 6: Release v1.2.0 (2 plans)

**Requirements:**
- RELEASE-01: Annotated git tag `v1.2.0` on final merged commit.
- RELEASE-02: GitHub release notes summarizing formal verification, Nyquist closure, input hardening, oracle completion, and debt cleanup in user-facing language.

**Success criteria:**

2. Release notes cover all 6 phases in user language.

## Explicitly NOT in v1.2

- Tier 2 SVA operators (`[->N]`, `[=N]`, `$changed`, `throughout`, `within`, `intersect`, `first_match`, sequence `and`/`or`) — defer to v1.3
- NFA composition vs token-passing extension — defer to v1.3 research spike
- IR node additions for new operators — defer to v1.3
- Cross-property CSE optimization — defer to v1.3
- C++ rewrite — defer to v2

## Validation Strategy

- Formal: yosys/sby equiv_induct for optimizer pass correctness
- Simulation: Existing dual-oracle (iverilog + Verilator) contract for all 736 tests
- Behavioral oracle: SVABehavioralSim per-cycle comparison for all sim tests
- Nyquist: Dedicated test per gap + programmatic invariant checks
- Input hardening: Negative tests for malformed inputs
